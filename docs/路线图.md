## 后续待解决事项

宗旨：**今后任何新增或修改，都要让用户尽可能自己能维护（交互友好），或者让 AI 直接去做；同时控制项目体量，不为不常用的功能付出维护成本。** 下面 1–6 项是下一阶段的任务（顺序不代表优先级），第 7 项为后期计划。

### 1. 新建合同模板：交互友好、顺畅的录入流程
- 现状：体检（`体检.bat`）+ AI 按 skill 分步处理；拆原子靠 AI 每次写一次性脚本；`type.yaml` 已让新类型无需改代码；拆完后可在条款维护页面逐条校对。
- 要做：
  - [ ] 表单新增“新建合同类型”向导：上传母本 → 显示体检结果（问题清单、结构大纲）→ 确认章范围与章代码（拆分设置）→ 一键生成原子草稿、配方、`type.yaml`、变量字典雏形 → 在条款维护中逐条校对 → 标变量 → 启用。
  - [ ] 通用拆原子工具（替代每次的一次性脚本）；用 F520 PO 母本重新生成 PO 库做回归，确认与现有库一致。
  - [ ] 体检识别手打编号（章号“一、”“第X章”，条款号“1.1”）；支持中文单语、英文单语、中英对照三种结构。
  - [ ] 样式模板、封面、价格表等块的生成（目前由 AI 手工处理）。
  - [ ] 试用：S416 VLCC 采购订单（中文版已完成体检与评审，见 `new_types/S416/`；需同时适用材料类和设备类物资）。

### 6. 精简项目体量：架构、功能、代码

- 第一步做盘点：目前代码约 3700 行（组装引擎约 1100、条款维护约 900、表单页面约 1000、新增类型工具约 560），测试约 500 行、快照 1.3 MB、测试运行约 2.5 分钟。逐项列出用途、使用频率、维护成本，给出“保留 / 合并 / 删除”建议，确认后再动手。
- 初步候选（待盘点确认）：
  - [ ] `原子总览.md` + `atom_index.py`：条款维护页面已能按章浏览和查找，总览可能多余。
  - [ ] 原子头信息中的 `引用`、`变量`、`选项`、`母本编号`、`版本`：代码不使用，且改条款后会过期。
  - [ ] `--标注`（变量标注版）、`--母本`（母本回归）：只在新增类型时用，可并入“新建合同类型”向导或测试。
  - [ ] 体检（`master_parser.py`、`health_check.py`、`体检.bat`）：并入“新建合同类型”向导，减少独立入口。
  - [ ] 表单中写死的变量分组和显示名改由变量字典提供，缩短 `ui/contract_form.py`（与待办 3 一起做）。
  - [ ] 测试：快照只保留正文文字与关键部件以减小体积；精简重复的页面用例，缩短运行时间。
  - [ ] 文档：流程图 PNG 与 Mermaid 重复维护（GitHub 可直接显示 Mermaid，可考虑去掉 PNG）；README 与 docs 的重复内容。
  - [ ] AI skill `contract-master-to-atoms`：与当前代码和流程不一致，随“新建合同类型”向导重写或删除。

### 7. 反哺反馈（后期）：从“生成版”到“签订版”的修改中持续改进
- 背景：程序生成的合同在谈判、审核到最终签订的过程中还会被修改。用户把这些修改以修订的形式记录下来，不定期汇总分析，找出模板和程序的问题，再改回内容库，形成闭环。
- 收集（用户日常）：
  - [ ] 约定存放方式：每份合同一个文件夹 `feedback/<合同编号>/`，放程序生成版（`output/` 中的 Word，及 `configs/` 中的配置）和最终签订版（或带修订痕迹的版本），可附一句说明（谁提出、为什么改）。
  - [ ] 签订版含商务机密：`feedback/` 只在本机保存、不进 git；汇总报告去掉金额、主体等敏感信息后才可提交。
- 分析（不定期，程序 + AI）：
  - [ ] 比对工具：读取生成版与签订版（或修订痕迹），把每处修改对应到条款 ID / 附件 / 变量（生成版由原子组装，可按段落定位），输出修改清单。
  - [ ] 汇总报告，按类别统计：
    - 高频被改的条款（哪些条款几乎每份都改、改成了什么）；
    - 缺少的变量（每份都要手改的数字、名称、日期 → 应改成变量）；
    - 缺少的写法（反复出现的同类改法 → 应加入选项库）；
    - 附件、版式、编号、翻译的问题；
    - 谈判中的常见让步与对方常提的要求；
    - 新出现的痛点与需求（进入路线图）。
  - [ ] 每类给出建议动作：改条款文字、新增变量 / 选项、调整默认值、加附件、修程序；用户确认后在条款维护页面或由 AI 落实，并记入修订记录。
- 与其他任务的关系：建议动作通过待办 2（条款 / 选项维护）、待办 3（变量管理）落实；比对工具可复用待办 2 中“Word 修订往返”的修订读取能力。
